# 策知

面向政策、标准、行业报告和资讯的本地采集与 AI 分析平台。当前采用轻量架构：

- 后端：FastAPI + SQLAlchemy + SQLite + APScheduler
- 前端：Vue 3 + Vite + Element Plus + ECharts
- 采集：httpx + BeautifulSoup + RSS/Atom + pypdf
- AI：Ollama、LM Studio、vLLM，以及常见 OpenAI 兼容 API

项目暂不依赖 PostgreSQL、Redis、Celery、Docker 或 MinIO，适合本地学习、原型验证和单机部署。

## 核心能力

### 本地账号与数据隔离

- 支持注册、登录、退出和 30 天本地会话。
- 密码使用带随机盐的 PBKDF2-SHA256 强哈希，数据库不保存明文密码。
- 关键词、数据源、文章、采集任务、AI 配置和分析记录均按账号隔离。
- 新注册账号会获得一套独立的默认数据源，不会看到其他账号的内容。
- 升级前已有数据会自动迁移到初始化管理员账号。

### 关键词策略

关键词不是一个孤立字符串，而是一套可维护的检索规则：

- 核心关键词：主题主名称，例如“设计制造工艺一体化”
- 扩展词：同义词、缩写和行业常用说法
- 精确短语：必须作为完整短语参与检索的表述
- 排除词：过滤招聘、培训等无关结果
- 限定站点：只检索指定域名
- 数据源：为每个策略选择权威站点、RSS/Atom 或通用搜索
- 采集间隔：每个策略独立配置 1 至 720 小时

编辑策略时可生成“查询预览”，在真正采集前核对系统将执行的检索组合。

### 三类数据源

| 类型 | 作用 | 当前行为 |
| --- | --- | --- |
| 权威定向 | 政府、主管部门、研究机构、标准组织和正式发布渠道 | 仅使用该站公开的站内 API、RSS 或目录适配器，不会隐式回退到搜索引擎 |
| RSS/Atom | 稳定获取网站新增内容 | 解析订阅源，按关键词策略筛选条目 |
| 通用搜索 | 补充发现新闻、解读和分散网页 | 只有用户明确选择时才使用 Bing；检测到验证码后自动冷却 12 小时 |

首次启动会预置中国政府网、国家数据局、工业和信息化部、国家发展改革委、国务院国资委、中国信通院、国家标准化管理委员会和 Bing 补充搜索。省市部门、行业协会、企业、高校和科研院所可在“数据采集 > 数据源”中继续添加。

工信部已内置公开 JSON API 适配器，国家数据局已内置官网 PIT 两阶段检索适配器。其他权威来源在配置原生适配器、RSS 或公开目录之前会明确显示“尚未配置原生发现方式”，不会把 `site:域名 关键词` 请求转交给 Bing。数据源的 `config.search_rule` 支持配置新的 JSON API 或 HTML 站内检索规则。

### 发现渠道与熔断

- “内容来源”和“发现渠道”是两个不同概念，任务错误会分别记录二者。
- 权威来源只能通过自身公开渠道发现内容，接口失败或返回空结果时不跨渠道重试。
- Bing 只承担明确选择的通用搜索任务，不再为权威来源兜底。
- Bing 首次返回 403、429、验证码或异常结果页后立即停止本次任务剩余请求，并进入 12 小时冷却期。
- 系统使用可识别的 `CezhiPolicyCollector` User-Agent，不伪装浏览器指纹。

### 可观测采集流水线

一次任务按以下阶段运行：

1. 生成查询计划
2. 从选定数据源发现 URL
3. 下载 HTML 或 PDF
4. 提取正文、发布日期、来源和附件
5. 按关键词策略计算相关性
6. 按规范化 URL 和内容哈希去重
7. 保存文献、PDF 和关键词关联
8. 记录每个 URL 的处理结果

默认每个关键词任务最多处理 20 个不同 URL，避免“多个扩展词 × 多个来源”让单次任务无限膨胀；该值可在 `backend/config.py` 中调整。

任务状态包括：`等待中`、`采集中`、`成功`、`部分成功`、`无新结果`、`被限制`、`失败`。任务明细会分别显示发现、下载、解析、新增、重复、低相关和失败数量，不再把“搜索异常”伪装成“成功但 0 条”。

直接发现的 PDF 会保存到 `data/pdfs/` 并提取文本。政策网页中的 PDF 附件也会自动归档首个可访问文件，附件文本会并入文献正文供 AI 分析；其余附件链接保留在详情页。

## 推荐使用顺序

1. 在“数据采集 > 数据源”中确认需要的权威站点已启用。
2. 在“关键词策略”中补充扩展词、精确短语和排除词。
3. 生成查询预览，确认检索范围后保存。
4. 手动执行一次“采集”，到“任务记录”查看各 URL 的处理明细。
5. 到“采集信息”筛选、浏览、收藏或下载文献。
6. 在“AI 分析”中选择 Ollama 或 API 厂商，刷新模型列表并测试连接。
7. 对采集文献执行摘要、词云、图表分析或上下文问答。

## 定时采集

APScheduler 在 FastAPI 进程内运行，每 30 分钟检查一次启用的关键词。只有超过该关键词自身 `采集间隔` 的任务才会进入队列，同一关键词已有等待或运行任务时不会重复创建。

本地架构下请只运行一个后端进程。启动多个 Uvicorn/Gunicorn worker 会各自启动一份 APScheduler，造成重复调度。

## AI 配置

系统提供 NVIDIA NIM、Kimi、Gemini、DeepSeek、MiniMax、阿里云百炼、百度千帆、硅基流动、火山方舟、智谱、OpenAI、Claude、Grok、OpenRouter 等预设。选择厂商后会自动填入 Base URL，API Key 始终由使用者自行填写。

本地模型支持 Ollama、LM Studio 和 vLLM。典型 Ollama 地址为：

```text
http://127.0.0.1:11434/v1
```

供应商卡片支持拖动排序，顺序按账号保存在 SQLite。NVIDIA 的 `429/529/5xx` 和其他临时服务错误会自动按 1、2、4 秒退避重试；Moonshot 等提供商的 `400` 响应会显示上游返回的具体错误，而不是只显示通用 HTTP 链接。

## 单机服务器部署

当前版本可采用“Vue 静态文件 + 单个 FastAPI 进程 + SQLite + 本地 PDF 目录”的方式部署。构建前端：

```powershell
cd frontend
npm run build
```

后端使用单 worker 运行：

```powershell
cd backend
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1
```

需要长期运行时，可再使用操作系统服务管理工具守护该进程。SQLite 数据库和 `data/pdfs/` 应定期整体备份。

## robots.txt 合规

系统**默认遵守**目标网站的 robots.txt 协议（`CRAWLER_RESPECT_ROBOTS_TXT = True`）。在抓取任何 URL 之前，爬虫会自动获取并缓存该域名的 `/robots.txt`，解析 `User-agent: *` 下的 `Allow` 和 `Disallow` 规则，被禁止的路径将被跳过并标记为 `blocked` 状态。

系统同时启用 `CRAWLER_ROBOTS_FAIL_CLOSED = True`：`robots.txt` 明确返回 404 时视为网站未发布规则；出现超时、403、429 或服务器错误时，系统无法确认许可范围，默认停止该域名的本次抓取。相同长度规则冲突时 `Allow` 优先，更具体的路径规则优先。

robots.txt 本身不是法律条文，但属于判断自动访问是否符合站点意愿的重要合规信号之一。遵守 robots.txt 并不当然代表采集行为完全合法，仍需同时考虑网站服务条款、数据性质、采集强度、使用目的和知识产权要求。

如需在特殊场景下关闭此检查（不推荐），可在 `backend/config.py` 中设置 `CRAWLER_RESPECT_ROBOTS_TXT = False`，但使用者需自行承担由此产生的全部法律风险。
